# Prisma ORM 7.8.0 Upgrade Design

## Overview

Vetching Corporation 사내 Prisma ORM fork를 6.17.1에서 7.8.0으로 업그레이드한다.
prisma(TypeScript)와 prisma-engines(Rust) 두 레포를 모두 업그레이드하며, 기존 리베이스 전략을 유지한다.

## Motivation

- Query Plan 캐싱, SQL Comments(sqlcommenter), 중첩 트랜잭션(Savepoints), Prisma Studio 등 v7 신기능 활용
- upstream과의 버전 격차 해소
- api-server Phase 2 (DB Read Replication 도입)의 선행 조건 — 참조: `api-server/docs/superpowers/specs/2026-05-19-phase2-read-replication-design.md`

## Prisma 6.17.1 → 7.8.0 Breaking Changes (영향 있는 것만)

### Engine Architecture

Rust 바이너리 엔진 완전 제거. Query Compiler(WASM) + Query Interpreter(JS) + Driver Adapter가 유일한 아키텍처. 포크에서 이미 이 아키텍처를 사용 중이므로 방향은 동일.

### Generator

- `prisma-client-js` → `prisma-client` 기본값 변경 (포크는 이미 `prisma-client` 사용 중)
- `output` 경로 필수화 (포크는 이미 사용 중)
- `compilerBuild` 옵션 추가 (`fast` | `small`, v7.3.0+)

### Client Instantiation

- `new PrismaClient()` 시 adapter 필수 전달 (포크는 이미 adapter 사용 중)
- `datasource.directUrl` 제거

### Config

- `prisma.config.ts` 필수화 (introspection/migration 시)
- `.env` 자동 로딩 제거
- `datasource.url`이 schema.prisma가 아닌 `prisma.config.ts`에서 설정
- downstream api-server에서도 `prisma.config.ts` 마이그레이션 필요 (별도 작업)

### Removed

- `LibraryEngine`, `BinaryEngine`, `DataProxyEngine`, `AccelerateEngine` — 모두 제거
- `metrics` previewFeature 제거
- 다수의 `PRISMA_*` 환경 변수 제거
- Driver Adapter 이름 표준화 (`PrismaBetterSQLite3` → `PrismaBetterSqlite3` 등)

### Internal File Relocations (커스텀 코드에 영향)

- `packages/client/.../types/JsonProtocol.ts` → **삭제됨**. v7에서는 `packages/json-protocol/src/index.ts`로 이동
- `Executor.ts`에 `SqlCommenterQueryInfo` 추가 (SQL Comments 지원)
- `QueryCompiler.ts` 인터페이스 변경 확인 필요

### New Features (활용 대상)

- Query Plan 캐싱 (`queryPlanCacheMaxSize`, v7.4.0+)
- SQL Comments / sqlcommenter (v7.1.0+)
- 중첩 트랜잭션 / Savepoints (v7.5.0+)
- Prisma Studio (완전 재구축)
- Partial Indexes (Preview, v7.4.0+)

### Read Replica 관련

v7의 `@prisma/extension-read-replicas`는 extension-level URL 라우팅이며 core runtime 통합이 아님. 사내 fork의 custom adapter-level `{ primary, replica }` 라우팅과는 별개 구현. 두 방식의 병행 사용은 지원하지 않으며, custom core-level 구현만 유지한다.

## Upgrade Strategy: Rebase

### Execution Order

prisma-engines의 custom WASM이 Phase 3(Multi-tenant) 검증과 Phase 5(lockfile 확정)에 필요하다. Phase 1/2(CI, CLI)는 engines 없이도 진행 가능.

```
prisma-engines (Rust)                    prisma (TypeScript)
─────────────────                        ──────────────────
1. typescript-engine/7.8.0/base 생성     4. typescript-engine/7.8.0/base 생성
   (6.17.1/base에서 fork)                   (6.17.1/base에서 fork)
2. base(7.8.0) 위로 리베이스             5. Phase 1~2 리베이스 (engines 불필요)
   (커스텀 3커밋 충돌 해결)
3. WASM 빌드 & 배포 (CI)                6. base(7.8.0) 위로 리베이스
                                            Phase 3~4 리베이스 (engines WASM 필요)
                                         7. Phase 5: WASM 버전 교체 + pnpm-lock.yaml 갱신
                                         8. prisma-client & prisma-cli 배포 (CI)
```

### Branch Creation (양쪽 레포 동일 패턴)

```bash
# 1. custom-only 커밋 범위 확인 (dry-run)
git log --oneline main..typescript-engine/6.17.1/base

# 2. 새 브랜치 생성 및 rebase
git checkout typescript-engine/6.17.1/base
git checkout -b typescript-engine/7.8.0/base
git rebase --onto base main typescript-engine/7.8.0/base
# → main 이후의 custom-only 커밋만 base(7.8.0) 위로 이전
#   upstream 커밋은 base에 이미 포함되어 있으므로 중복되지 않음
```

**Upstream anchor**: `base` 브랜치의 HEAD 커밋을 rebase 시작 전 기록하여 재현 가능하게 한다.

주요 충돌 파일:

- `getPrismaClient.ts` — v7 engine 초기화 대폭 변경. `$context()`, `$setGlobalSchema()`, `adapter { primary, replica }` 전부 재적용

- `serializeJsonQuery.ts` — schemaRequest 직렬화 재적용
- `packages/json-protocol/src/index.ts` — v7에서 `JsonProtocol.ts`가 이동된 위치. `DynamicSchema` 타입과 `schemaRequest` 필드 재적용
- `QueryCompiler.ts` (`client-common`) — `compile(request, schemaRequest)` / `compileBatch(request, schemaRequest)` 시그니처 재적용
- `Executor.ts` — v7에서 `SqlCommenterQueryInfo` 추가됨. replica 라우팅 + SQL Comments 호환성 확인
- `LocalExecutor.ts` — 읽기 오퍼레이션 라우팅 로직 재적용 + `forceWriter` ALS 지원 (아래 참조)
- `Engine.ts` — `adapterReplica` 필드 재적용
- `JsApi.ts` — `schema` 인수 재적용

**필수 추가 작업 (Phase 3):**

1. **Query Plan Cache + schemaRequest**: v7 `ClientEngine.ts`의 캐시 키에 schemaRequest 해시를 포함하여 테넌트 간 query plan 오염 방지. schemaRequest는 작은 JSON(`{"hospital_template": "hospitalN"}`)이므로 해시 추가만으로 충분하며, LRU `queryPlanCacheMaxSize`가 메모리 상한을 관리.

2. **`forceWriter` ALS 라우팅** (Phase 2 Read Replication 설계 반영):
   기존 `$setGlobalSchema()`의 `RequestContextPayload`를 확장하여 단일 ALS 인스턴스에서 `forceWriter`도 관리한다. 별도 ALS를 만들지 않으므로 스코프 누수/중첩 문제가 없다.

   **설계:**

   ```typescript
   // RequestContextPayload 확장
   type RequestContextPayload = {
     dynamicSchemas?: DynamicSchema[]
     forceWriter?: boolean              // 새 필드
   }

   // PrismaClient에 $forceWriter 메서드 추가
   $forceWriter<T>(cb: () => Promise<T>): Promise<T> {
     const current = this._requestContext.getStore() ?? {}
     return this._requestContext.run({ ...current, forceWriter: true }, cb)
   }
   ```

   **사용 예시 (api-server):**

   ```typescript
   // Express middleware — 테넌트 스키마 설정
   prisma.$setGlobalSchema('hospital5', async () => {
     // Apollo mutation plugin — writer 강제
     await prisma.$forceWriter(async () => {
       // schema=hospital5 AND forceWriter=true
       // spread로 부모 dynamicSchemas 보존
     })
     // schema=hospital5, forceWriter=false (읽기는 replica)
   })
   ```

   **LocalExecutor 라우팅:**

   ```typescript
   const ctx = this.#requestContext?.getStore()
   const forceWriter = ctx?.forceWriter ?? false
   const queryable = transaction
     ? transactionManager.getTransaction(...)
     : !forceWriter && replica && readOperations.includes(operation)
       ? replica
       : primary
   ```

   v7 `LocalExecutor`(115줄)는 replica 라우팅이나 ALS 참조를 위한 확장점이 없으므로, 이 파일은 직접 수정(fork)해야 한다. 향후 upstream 업그레이드 시에도 이 파일은 매번 충돌이 발생하는 fork 비용을 감수해야 하며, Phase 3 고위험 항목으로 관리한다.

3. **`relationJoins` preview feature 호환**: v7.8.0 base에서 `relationJoins`는 여전히 preview feature이지만, `adapter-pg`에서 `supportsRelationJoins: true`로 지원됨. api-server Phase 2에서 활성화 예정이므로, fork의 read replication 라우팅이 relation JOIN 쿼리에서도 정상 동작하는지 검증 필요.

**Phase 4: WASM Version Update + Lockfile (2커밋)** — 승인 게이트 4

- `2d40fa2de` update query compiler version
- `77cd0a1c2` update query-compiler-wasm version

## Downstream Dependencies

## Out of Scope

- CI/빌드 워크플로 변경은 별도 처리 (사용자가 직접 관리)
- 버전 명명은 CI에서 자동 처리
- api-server 코드 변경 (Prisma fork 업그레이드 후 별도 진행, Phase 2 설계 참조)
- `@prisma/extension-read-replicas` extension과의 병행은 지원하지 않음 (custom core-level 구현만 유지)
