Overview

Vetching Corporation 사내 Prisma ORM fork를 6.17.1에서 7.8.0으로 업그레이드한다. prisma(TypeScript)와 prisma-engines(Rust) 두 레포를 모두 업그레이드하며, 기존 리베이스 전략을 유지한다.

Motivation

  • Query Plan 캐싱, SQL Comments(sqlcommenter), 중첩 트랜잭션(Savepoints), Prisma Studio 등 v7 신기능 활용
  • upstream과의 버전 격차 해소
  • api-server Phase 2 (DB Read Replication 도입)의 선행 조건

Breaking Changes 6.17.1 → 7.8.0

Engine Architecture

Rust 바이너리 엔진 완전 제거. Query Compiler(WASM) + Query Interpreter(JS) + Driver Adapter가 유일한 아키텍처. 포크에서 이미 이 아키텍처를 사용 중이므로 방향은 동일.

Generator

  • prisma-client-js → prisma-client 기본값 변경 (포크는 이미 prisma-client 사용 중)
  • output 경로 필수화 (포크는 이미 사용 중)
  • compilerBuild 옵션 추가 (fast | small, v7.3.0+)

Client Instantiation

  • new PrismaClient() 시 adapter 필수 전달 (포크는 이미 adapter 사용 중)
  • datasource.directUrl 제거

Config

  • prisma.config.ts 필수화 (introspection/migration 시)
  • .env 자동 로딩 제거
  • datasource.url이 schema.prisma가 아닌 prisma.config.ts에서 설정
  • downstream api-server에서도 prisma.config.ts 마이그레이션 필요 (별도 작업)

Removed

  • LibraryEngine, BinaryEngine, DataProxyEngine, AccelerateEngine — 모두 제거
  • metrics previewFeature 제거
  • 다수의 PRISMA_* 환경 변수 제거
  • Driver Adapter 이름 표준화 (PrismaBetterSQLite3 → PrismaBetterSqlite3 등)

Internal File Relocations (커스텀 코드에 영향)

  • packages/client/.../types/JsonProtocol.ts → 삭제됨. v7에서는 packages/client-engine-runtime/src/json-protocol.ts로 이동
  • Executor.ts에 SqlCommenterQueryInfo 추가 (SQL Comments 지원)
  • QueryCompiler.ts 인터페이스 변경 확인 필요

New Features (활용 대상)

  • Query Plan 캐싱 (queryPlanCacheMaxSize, v7.4.0+)
  • SQL Comments / sqlcommenter (v7.1.0+)
  • 중첩 트랜잭션 / Savepoints (v7.5.0+)
  • Prisma Studio (완전 재구축)
  • Partial Indexes (Preview, v7.4.0+)

Read Replica 관련

Note

v7의 @prisma/extension-read-replicas는 extension-level URL 라우팅이며 core runtime 통합이 아님. 사내 fork의 custom adapter-level { primary, replica } 라우팅과는 별개 구현. 두 방식의 병행 사용은 지원하지 않으며, custom core-level 구현만 유지한다.

Upgrade Strategy: Rebase

필수 추가 작업 (Phase 3)

1. Query Plan Cache + schemaRequest

v7 ClientEngine.ts의 캐시 키에 schemaRequest 해시를 포함하여 테넌트 간 query plan 오염 방지. schemaRequest는 작은 JSON({"hospital_template": "hospitalN"})이므로 해시 추가만으로 충분하며, LRU queryPlanCacheMaxSize가 메모리 상한을 관리.

2. forceWriter ALS 라우팅

현재 6.17.1 fork의 LocalExecutor는 readOperations.includes(operation) 조건만으로 라우팅한다. api-server Phase 2 설계에서는 mutation GraphQL resolver 스코프 내 모든 쿼리(nested read 포함)를 writer로 강제하기 위해 AsyncLocalStorage forceWriter 플래그를 추가해야 한다. 

// v7 LocalExecutor에 추가할 라우팅 로직
const forceWriter = asyncLocalStorage.getStore()?.forceWriter ?? false
const queryable = transaction
  ? transactionManager.getTransaction(...)
  : !forceWriter && replica && readOperations.includes(operation)
    ? replica
    : primary
3. relationJoins preview feature 호환

v7.8.0 base에서 relationJoins는 여전히 preview feature이지만, adapter-pg에서 supportsRelationJoins: true로 지원됨. api-server Phase 2에서 활성화 예정이므로, fork의 read replication 라우팅이 relation JOIN 쿼리에서도 정상 동작하는지 검증 필요.

Out of Scope
